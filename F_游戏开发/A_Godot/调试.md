# GDExtension调试

## 使用 VS Code 调试 GDExtension（最常用）

这个方法适合你已经在使用 VS Code 开发 GDExtension 的情况，它能在启动时直接附加上调试器。

#### 1. 编译带调试符号的扩展库

首先，你需要编译一个包含调试符号的扩展库。在你的项目根目录下，使用 SCons 并添加 `dev_build=yes` 参数。

bash

```
scons target=template_debug dev_build=yes
```



这会生成一个文件名带有 `.dev` 的库文件（例如 `libyinglong.windows.template_debug.dev.x86_64.dll`）。

#### 2. 创建 VS Code 调试配置文件 (`.vscode/launch.json`)

在你的项目根目录下创建 `.vscode` 文件夹，并在其中创建 `launch.json` 文件。这是一个用于调试 Godot 编辑器或游戏项目的配置模板。

json

```
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Debug GDExtension in Editor",
            "type": "cppvsdbg", // Windows 用 cppvsdbg，Linux/macOS 用 cppdbg
            "request": "launch",
            "program": "C:/path/to/your/godot.exe", // 改成你的 Godot 可执行文件路径
            "args": [
                "--editor",          // 以编辑器模式启动，方便调试初始化流程
                "--path",
                "${workspaceFolder}/path/to/your/godot-project", // 改成你的 Godot 项目路径
                "--verbose"          // 输出更详细的日志
            ],
            "stopAtEntry": false,
            "cwd": "${workspaceFolder}",
            "environment": [],
            "console": "internalConsole"
            // "preLaunchTask": "build-scons" // 可选：调试前自动编译
        }
    ]
}
```



- **`type`**：如果使用 MSVC 编译器，Windows 下推荐使用 `cppvsdbg`；Linux/macOS 下使用 `cppdbg`。
- **`program`**：必须修改为你的 Godot 可执行文件（`godot.exe` 或 `godot`）的**绝对路径**。
- **`args`**：启动参数非常重要：
  - `--editor`：启动 Godot 编辑器。如果你想调试游戏运行时的代码，可以不加这个参数，直接启动游戏场景。
  - `--path`：指定你的 Godot 项目目录（包含 `project.godot` 文件的文件夹）。
  - `--verbose`：输出详细日志，有助于发现早期错误。

#### 3. 配置 `.gdextension` 文件

为了让 Godot 加载你带调试符号的库，需要修改项目里的 `.gdextension` 文件，将对应平台的库路径指向 `.dev` 版本。

ini

```
[libraries]
windows.debug.x86_64 = "res://bin/libyinglong.windows.template_debug.dev.x86_64.dll"
```



#### 4. 开始调试

1. 在 VS Code 中，切换到“运行和调试”面板。
2. 在顶部的下拉菜单中选择你刚刚创建的配置（如 `Debug GDExtension in Editor`）。
3. **在 C++ 代码中设置断点**。
4. 点击绿色的启动按钮（▷）。

现在，VS Code 会启动 Godot 编辑器，并在执行到你的 C++ 代码断点时暂停。如果程序在到达断点前就崩溃了，调试器也会停下，并显示崩溃时的调用堆栈。

### 💻 方法二：使用 Visual Studio 调试（Windows 下更稳健）

如果你觉得 VS Code 的调试体验不够稳定，可以尝试功能更强大的 Visual Studio 调试 GDExtension。你不需要把整个项目转换成 VS 工程，只需使用它的“附加到进程”或创建一个空的 NMake 项目来启动调试。
